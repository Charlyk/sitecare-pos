## Additional Implementation Notes (non-template, for executor traceability)

- **Reprint button placement (resolves Claude's Discretion item):** the read-only variant renders in the exact same position as the live `!readOnly` row it mirrors — immediately below `<ThermalTicket .../>`, same `display: flex; gap: 8px` row, "Print kitchen" first (`.btn-secondary`, `flex: 1`) then "Print customer" second (`.btn-primary`, `flex: 1`), same `<Icon name="printer" size={14} />` + label composition. Per D-03, this is an **added** `readOnly &&` block, not a widened `!readOnly` guard — the existing live-only Advance button below stays gated behind `!readOnly` exactly as today.
- **Disabled style — exact values, not the offline convention:** use inline `opacity: 0.5; pointerEvents: 'none'; cursor: 'not-allowed'` (matching `screen-history.jsx:843`'s Export button, per D-05) plus the native `disabled` attribute. Do **not** reuse `.btn-disabled-offline` (`opacity: 0.45`) — that class is reserved for the connectivity-offline convention (a different semantic and a different opacity value) and mixing the two would introduce an inconsistent third disabled-opacity value into the app.
- **`placed_at` CSV format (resolves Claude's Discretion item):** `YYYY-MM-DD HH:mm` in 24-hour local time (e.g. `2026-07-18 14:32`) — sortable in any spreadsheet tool, contains no comma (avoids incidental CSV-escaping edge cases), and avoids ISO's `T` separator, which some regional Excel builds mis-parse as text rather than a datetime.
- **Default export filename (per locked D-14):** `orders_<from>_<to>.csv` using the same `YYYY-MM-DD` values already driving the active period query, e.g. `orders_2026-07-01_2026-07-18.csv`.
