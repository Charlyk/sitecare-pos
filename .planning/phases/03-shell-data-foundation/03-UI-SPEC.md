Accent reserved for: active nav state, primary CTA buttons, focus ring, count badges. NOT for the offline banner.

**Phase 3 specific — offline banner color:**
- Background: `hsl(38 92% 50% / 0.12)` — amber tint (matches existing `.chip-amber` pattern)
- Left border: 3px solid `hsl(38 92% 50%)` — amber (hsl(38, 92%, 50%))
- Icon color: `hsl(30 80% 38%)` — amber dark (matches `.chip-amber` foreground)
- Text color: `hsl(30 80% 38%)` — amber dark, same as icon
- Severity: **warning** (amber), NOT destructive red. Rationale: offline is a transient state, not a failure. Red would alarm staff unnecessarily. The existing `.chip-amber` palette already establishes the warning semantic.

Amber values are sourced directly from the existing `.chip-amber` rule in `src/styles.css`:
```

```
Banner uses `/ 0.12` (slightly lighter than chip) to fill a full-width strip without overwhelming.

Source: `src/styles.css` `.chip-amber` — confirmed. No new color values introduced.

## Component Inventory: Offline Banner

### OfflineBanner Component

**File:** `src/offline-banner.jsx`

**Render condition:** `isOffline === true` — not rendered when `isOffline === false`

**Position in DOM:** Immediately after the opening of `.main > .content` wrapper, before `{children}`. It does NOT sit inside `.topbar`. It does NOT span the sidebar.

```
.main
  .topbar           ← existing, not modified
  .content
    <OfflineBanner> ← new, first child of .content when isOffline=true
    {children}      ← active screen
```

**Dimensions:**
- Height: 40px (fixed)
- Width: 100% of `.content` column
- Horizontal padding: 24px left and right

**Visual anatomy (left to right):**
1. Icon: `<Icon name="wifi" size={16} />` — amber dark color
2. Gap: 8px
3. Primary message text: 13px weight 600 — `t('offline_banner_title')`
4. Gap: 8px
5. Secondary message text: 13px weight 400 color `hsl(30 80% 38% / 0.75)` — `t('offline_banner_sub')`

No retry button. Reconnection is automatic (D-09 from CONTEXT.md). A button would imply manual recovery; the auto-reconnect contract makes it misleading.

**Border:** 3px solid `hsl(38 92% 50%)` on left edge only (left border accent). No top/right/bottom border.

**Bottom border separator:** 1px solid `hsl(38 92% 50% / 0.25)` to visually separate banner from screen content below.

**Animation — enter:** `slideDown` — 200ms, `cubic-bezier(0.4, 0, 0.2, 1)` (matches `--sc-easing`)
```css
@keyframes slideDown {
  from { transform: translateY(-100%); opacity: 0; }
  to   { transform: translateY(0);     opacity: 1; }
}
```
Animation duration: `--sc-duration` (200ms).

**Animation — exit:** CSS conditional render — component unmounts when `isOffline` flips false. No exit animation needed (banner disappears instantly on reconnect is the appropriate UX — confirms recovery immediately).

**CSS class:** `.offline-banner` — add to `src/styles.css`

```css
.offline-banner {
  height: 40px;
  padding: 0 24px;
  display: flex;
  align-items: center;
  gap: 8px;
  background: hsl(38 92% 50% / 0.12);
  border-left: 3px solid hsl(38 92% 50%);
  border-bottom: 1px solid hsl(38 92% 50% / 0.25);
  color: hsl(30 80% 38%);
  font-size: 13px;
  font-family: var(--sc-font-sans);
  font-weight: 600;
  animation: slideDown var(--sc-duration) var(--sc-easing);
  flex-shrink: 0;
}
.offline-banner .banner-sub {
  font-weight: 400;
  opacity: 0.75;
}
@keyframes slideDown {
  from { transform: translateY(-40px); opacity: 0; }
  to   { transform: translateY(0);     opacity: 1; }
}
```

## Component Inventory: Offline Disabled Button State

### Disabled State for Mutating Buttons

**Applies to:** `Accept`, `Advance`, `Cancel`, `Create Order` buttons — the four mutating actions listed in D-11 and OFF-03.

**Trigger:** `isOffline={true}` prop on the screen.

**Implementation pattern:** Each screen adds `disabled={isOffline}` to its mutating buttons AND the `.btn-offline-disabled` class modifier when offline. The native `disabled` attribute prevents keyboard activation; the CSS controls appearance.

**Visual treatment:**

| Property | Offline value | Normal value |
|----------|---------------|--------------|
| Opacity | 0.45 | 1 |
| Cursor | `not-allowed` | `pointer` |
| pointer-events | `none` (via CSS) | default |
| Background | unchanged — retains btn class color | unchanged |
| Text | unchanged | unchanged |

Opacity 0.45 chosen (not 0.4 or 0.5): consistent with existing "greyed-out, not hidden" principle. At 0.45 the button color remains identifiable (staff see what they would press) while being clearly unavailable.

**CSS modifier class:** `.btn-disabled-offline`

```css
.btn-disabled-offline {
  opacity: 0.45;
  cursor: not-allowed;
  pointer-events: none;
}
```

Apply in JSX: `className={`btn-primary${isOffline ? ' btn-disabled-offline' : ''}`}`

**Tooltip on hover:** None. Rationale: `pointer-events: none` prevents hover events entirely. A tooltip would require a wrapper element. The offline banner already explains WHY buttons are disabled — a tooltip would be redundant and adds implementation complexity.

**Which buttons are NOT affected:** Read-only/navigation actions (nav items, role switcher, language toggle, search, printer setup controls, settings controls). Only server-mutating actions are disabled.

## Copywriting Contract

All copy is bilingual. Keys must be added to `src/i18n.jsx` under both `ro` and `en` objects.

| Element | Key | RO copy | EN copy |
|---------|-----|---------|---------|
| Banner primary message | `offline_banner_title` | `Conexiune întreruptă` | `Connection lost` |
| Banner secondary message | `offline_banner_sub` | `Reconectare automată în curs…` | `Reconnecting automatically…` |

**No other new copy is introduced in this phase.** All other strings (Accept, Cancel, etc.) already exist in i18n.jsx.

**Copy rationale:**
- "Conexiune întreruptă" / "Connection lost" — factual, not alarming. States the problem without blaming.
- "Reconectare automată în curs…" / "Reconnecting automatically…" — sets staff expectation that no manual action is needed, reduces unnecessary support calls.
- No "Please check your internet connection" — the SSE is internal API; it will self-heal. Staff cannot fix API outages.
- Ellipsis `…` in the sub-message signals an ongoing process (reconnecting), not a permanent error.

**Empty state copy:** Not applicable to this phase. Phase 3 does not introduce new list screens.

**Error state copy:** Not applicable. Offline is a transient state signaled by the banner; there are no new error dialogs.

**Destructive actions:** Not introduced in this phase. `Cancel` button treatment is inherited from Phase 1 design; disabling it when offline is a state change, not a new destructive confirmation flow.
