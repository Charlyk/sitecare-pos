<objective>
TRACER SLICE — prove the full branch-scoped-cache pattern end-to-end on ONE hook before mechanical expansion. Create the shared `unwrapSdkResult()` helper, fully retrofit `use-orders.js` (branch-scoped key + error path through the helper), move ONE invalidation site (`screen-orders.jsx:281` manual refresh) in lockstep, and prove it with tests (SC1 key-change, SC4 null-branch, SC3 err.code).

Purpose: Proving key + helper + invalidation + test once, end-to-end, catches any architectural dead-end after a single commit instead of after all 7 hooks are already rewritten. All remaining hooks (Plans 02–03) and invalidation sites (Plan 04) then expand mechanically from this proven slice.

Output: `unwrapSdkResult` in src/data.jsx; retrofitted use-orders.js; branch-scoped screen-orders.jsx refresh button; new data-unwrap-sdk-result.test.js; extended use-orders.test.js.

**Phase boundaries (out of scope — do NOT implement here):** Per **D-02**, this phase does NOT touch the branch switch flow/mutation that sets `currentBranch` — Phase 16 owns it; these keys merely *react* when it changes. Per **D-06**, this phase only *produces* `err.code`; it does NOT build the centralized `onError` handler or act on `BRANCH_INACTIVE`/`BRANCH_ACCESS_REVOKED`/`NO_BRANCH_ACCESS` — Phase 17 owns that.

**Known accepted regression window (flag, do not fix):** After this phase, `use-sse.js` still writes the unscoped `['orders']`/`['stats']` keys that no hook reads anymore — SSE live updates stop reaching the UI until Phase 15 branch-prefixes those writes. This is an intentional phase boundary (RESEARCH Pitfall 3); if Phase 14 and Phase 15 ship as separate deploys, call it out to the operator as a deploy-ordering constraint. Do NOT touch use-sse.js here.
