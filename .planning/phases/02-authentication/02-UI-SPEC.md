## Layout Architecture

The login screen uses a **two-column split layout** filling the full app window. There is no sidebar, no topbar, and no shell wrapper.

```
┌─────────────────────────────────────────────────────────────────┐
│ [brand panel — flex col, ~1fr] │ [form panel — ~1.1fr] │
│ left: brand identity, hero │ right: login form │
│ copy, stats, receipt card │ centered, max-width 420px │
└─────────────────────────────────────────────────────────────────┘
```

CSS:
```css
.login-body {
  display: grid;
  grid-template-columns: 1fr 1.1fr;
  height: 100%;
}
```

> Source: `login.html` `.login-body` selector. Decision D-02.

## States and Interactions

### Form Validation States

| State | Trigger | Email field | Password field | Button |
|-------|---------|-------------|----------------|--------|
| Idle / empty | Initial | Normal border | Normal border | Disabled (`opacity` via `!canSubmit`) |
| Typing | User input | Normal border | Normal border | Enabled when both non-empty |
| Email error | Submit with invalid email regex | `.err` class | Normal | Stays disabled |
| Credential error | API returns 401 | `.err` class | `.err` class | Re-enabled after error |
| Loading | Submit in progress | Locked (disabled) | Locked (disabled) | Spinner state |
| Success | API 200 | — | — | Redirect to Orders screen |

Error message renders in `.field-error` immediately below the relevant field.

### Session Expiry Toast

When a 401 is received mid-session or on cold-start with a stale token:

1. Show a toast from the existing `.toast` / `.toast-stack` component (already in `src/styles.css`)
2. Copy (RO): `Sesiunea a expirat — te rugăm să te autentifici din nou`
3. Copy (EN): `Session expired — please log in again`
4. Toast icon: `<Icon name="alert" size={16} />` in `.toast-icon` (sage tinted)
5. After **2 seconds**, navigate to login screen (`screen = 'login'` in Zustand)
6. Do not clear the email field on redirect — staff can re-enter password without retyping email

### "Forgot Password?" Link Interaction

- Rendered in **two locations**: (a) inside password field label row; (b) right side of `.form-foot`
- Click calls `open('https://restaurant.sitecare.ro/reset-password')` from `@tauri-apps/plugin-shell`
- No modal, no in-app UI — opens system browser immediately
- Cursor: pointer; hover: `text-decoration: underline`

### Language Switcher

- Position: `.form-top`, top-right of form panel
- Toggle between RO and EN
- Persists to Zustand store `lang` key (already wired in `store.js`)
- Active button: white bg, `--sc-primary` text, `0 1px 2px rgba(0,0,0,0.06)` shadow
- Inactive button: transparent bg, `--sc-muted-foreground` text

### Proactive Token Refresh (invisible to user)

- No UI element; implemented in `useAuth` hook
- On successful refresh: timer reset silently
- On refresh failure: triggers session expiry toast + 2s redirect

## Auth Guard Visual Contract

When `isAuthenticated === false` (checked on cold start or after session expiry), `app.jsx` renders `<LoginScreen />` instead of `<Shell>`. The transition is:

- Cold start with valid token: `<Shell>` renders immediately (no login flash)
- Cold start with expired/missing token: `<LoginScreen />` renders immediately
- Mid-session expiry: toast appears over current screen → 2s → screen switches to `<LoginScreen />`

No loading spinner between cold-start check and render decision — the Keychain read is synchronous via Tauri IPC. If the IPC call is async, render a minimal loading state: white background with no content (not a spinner) while awaiting the result.
