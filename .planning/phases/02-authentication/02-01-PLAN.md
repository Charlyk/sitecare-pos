       ```rust
       // Prevents additional console window on Windows in release, DO NOT REMOVE!!
       #![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

       use keyring::Entry;

       #[tauri::command]
       fn store_token(token: String) -> Result<(), String> {
           Entry::new("sitecare-pos", "auth_token")
               .map_err(|e| e.to_string())?
               .set_password(&token)
               .map_err(|e| e.to_string())
       }

       #[tauri::command]
       fn get_token() -> Result<Option<String>, String> {
           let entry = Entry::new("sitecare-pos", "auth_token")
               .map_err(|e| e.to_string())?;
           match entry.get_password() {
               Ok(token) => Ok(Some(token)),
               Err(keyring::Error::NoEntry) => Ok(None),
               Err(e) => Err(e.to_string()),
           }
       }

       #[tauri::command]
       fn delete_token() -> Result<(), String> {
           let entry = Entry::new("sitecare-pos", "auth_token")
               .map_err(|e| e.to_string())?;
           match entry.delete_credential() {
               Ok(()) => Ok(()),
               Err(keyring::Error::NoEntry) => Ok(()), // idempotent — no error if already absent
               Err(e) => Err(e.to_string()),
           }
       }

       #[cfg_attr(mobile, tauri::mobile_entry_point)]
       pub fn run() {
           tauri::Builder::default()
               .plugin(tauri_plugin_store::Builder::new().build())
               .plugin(tauri_plugin_opener::init())
               .setup(|app| {
                   #[cfg(desktop)]
                   app.handle().plugin(tauri_plugin_window_state::Builder::default().build())?;
                   Ok(())
               })
               .invoke_handler(tauri::generate_handler![store_token, get_token, delete_token])
               .run(tauri::generate_context!())
               .expect("error while running tauri application")
       }
       ```

    Notes:
    - `keyring::Error::NoEntry` is the correct variant in keyring v3 for a missing credential.
    - `tauri_plugin_opener::init()` replaces the shell plugin for URL opening in Tauri v2.
    - `invoke_handler` registers all three commands; executor must list all three in the macro.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer→Rust IPC | JS calls invoke('store_token', { token }) — token travels over Tauri IPC |
| Keychain storage | OS credential store — accessible to processes with same bundle identifier |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | store_token IPC | mitigate | Token received is a JWT; the Rust side stores it verbatim — no parsing, no eval. Validation happens in the JS auth layer before invoke. |
| T-02-02 | Information Disclosure | Keychain read by another process | accept | macOS Keychain and Windows Credential Manager enforce app-bundle-level isolation. Acceptable for a desktop POS app. |
| T-02-03 | Elevation of Privilege | invoke() called from a malicious iframe | mitigate | Tauri v2 CSP restricts script-src to 'self'; no remote script can call invoke(). Capability model gates all IPC commands. |
</threat_model>
