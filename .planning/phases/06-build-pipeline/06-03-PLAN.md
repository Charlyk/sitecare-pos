<objective>
Configure tauri.conf.json with the updater endpoint, signing pubkey, and correct bundle targets. This plan also generates the Ed25519 signing keypair and documents the required GitHub Secrets the developer must add manually.

Purpose: Without a pubkey in tauri.conf.json, the updater plugin refuses to verify downloads and throws at runtime. Without createUpdaterArtifacts, no .sig files are produced. Without explicit bundle.targets, the CI macOS runner attempts unsupported Linux targets (Pitfall 5).
Output: Updated tauri.conf.json with full updater configuration. Developer briefed on keypair → GitHub Secret workflow.

BILD-03 note: Per D-03, Windows code signing is intentionally skipped. This plan produces the unsigned Windows .msi target. BILD-03 (SmartScreen-free install) is deferred. The plan documents this deferral explicitly but takes no signing action.
</objective>

  <action>
Edit src-tauri/tauri.conf.json with the following three changes. Read the current file first to preserve all existing content exactly.

**Change 1 — `bundle.targets`:** Replace `"targets": "all"` with `"targets": ["dmg", "msi"]`

Rationale: `"all"` on a macOS runner attempts Linux AppImage builds (Pitfall 5). Explicit targets prevent this. Only dmg (macOS) and msi (Windows) are needed per project scope.

**Change 2 — `bundle.createUpdaterArtifacts`:** Add `"createUpdaterArtifacts": true` to the `bundle` object.

This enables generation of:
- macOS: `SiteCare POS_VERSION_aarch64.app.tar.gz` + `.sig` file
- Windows: `SiteCare POS_VERSION_x64_en-US.msi.sig` file

**Change 3 — `plugins.updater`:** Add a new top-level `"plugins"` section:

```json
"plugins": {
  "updater": {
    "pubkey": "PASTE_PUBLIC_KEY_HERE",
    "endpoints": [
      "https://github.com/Charlyk/sitecare-pos/releases/latest/download/latest.json"
    ],
    "windows": {
      "installMode": "passive"
    }
  }
}
```

Replace `PASTE_PUBLIC_KEY_HERE` with the actual public key content from `~/.tauri/sitecare-pos.key.pub` that the developer provided in Task 1. If the developer typed "done" without providing the key, use the literal placeholder string `"PUBKEY_PLACEHOLDER"` — the developer can replace it manually. In that case, add a comment in the SUMMARY noting the pubkey must be filled in before the first CI run.

**installMode: passive** rationale: `passive` shows a progress bar and is the Windows default/recommended. `quiet` requires admin rights already held. `passive` is the safest choice per RESEARCH.md Alternatives Considered.

**BILD-03 deferral note:** Windows code signing is intentionally absent from this configuration per D-03. The Windows .msi will be unsigned. SmartScreen will show a "More info → Run anyway" prompt on first install — this is acceptable because the user installs the app personally. Azure Trusted Signing (~$10/month, no hardware token) is the deferred candidate when client volume makes manual installs impractical.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine → GitHub Secrets | Private signing key must flow via GitHub Secrets UI, never committed to repo |
| GitHub Releases CDN → app (updater endpoint) | latest.json fetched over TLS; Ed25519 sig in the manifest verified against pubkey in binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Spoofing | tauri.conf.json pubkey | mitigate | pubkey embedded in binary at build time; changing it requires a new release; old installs keep the old pubkey and cannot be fooled by a different keypair |
| T-06-03-02 | Tampering | Cargo.lock / tauri.conf.json in repo | accept | All config is in source control; tampering is visible in git history; branch protections on main mitigate unauthorized PRs |
| T-06-03-03 | Disclosure | TAURI_SIGNING_PRIVATE_KEY in GitHub Secrets | mitigate | GitHub encrypts secrets at rest; secrets not available to fork PRs; if leaked, rotate key and ship a new version (old installs cannot verify updates until reinstalled) |
| T-06-03-04 | Elevation of Privilege | Windows unsigned MSI | accept | Per D-03, code signing deferred. SmartScreen click-through acceptable for personal installs. Azure Trusted Signing is the deferred candidate (no hardware token, CI-friendly, ~$10/month). |
</threat_model>
