# Phase 7 — UI Design Contract

> Visual and interaction contract for History Screen Foundation. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. This phase inherits a mature, already-shipped design system
> (`src/colors_and_type.css` + `src/styles.css`) — this contract **binds to** that system rather
> than inventing a new one, per CLAUDE.md's design-fidelity rule. The only intentional departures
> from the design source (`screen-history.jsx`) are D-06/D-07/D-15, all user-directed (see
> `07-CONTEXT.md`).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled CSS custom properties, no shadcn/Tailwind in this project |
| Preset | not applicable |

- Card radius: `16px` (`.card`), pill radius: `999px`

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row cell text — customer name, time, payment label) | 13.5px | 600 | 1.3 |
| Label (column headers, tile labels — uppercase, 0.06em tracking) | 10.5px | 700 | 1.3 |
| Heading (day-group header label) | 12.5px | 800 | 1.2 |
| Display (summary tile value — largest number on screen) | 20px | 900 | 1.1 |

**Documented weight exceptions** (this project's shipped design system already uses 4 weights
consistently across v1.0 screens — CLAUDE.md forbids changing typography without instruction, so
the existing multi-weight system is carried forward rather than collapsed to 2 for this phase):
- Order number (row) / Total (row): 14px–14.5px / weight **900** / tabular-nums, tracking -0.01em
- Day-group revenue figure: 11.5px / weight **800** / color `var(--sc-primary)`
- Empty-state heading: 15px / weight **600**; empty-state body: 13px / weight **400**

All numeric figures (totals, tile values, day revenue) use `font-variant-numeric: tabular-nums`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--sc-background` `hsl(40 60% 97%)` (warm cream) | Page background behind `.content-pad` |
| Secondary (30%) | `--sc-card` `#fff` (cards, table body) + `#faf6ec` / `#fcfaf4` (table header band, day-group header band — same family, slightly warmer) | Table card, summary tiles, day-group header bands |
| Accent (10%) | `--sc-primary` sage `hsl(120 14% 49%)` | See reserved list below |
| Destructive | `--sc-destructive` / `chip-red` `hsl(0 84% 60%)` | Canceled status chip + row dim/strikethrough |
| Warning (third status, required by D-02) | `chip-amber` `hsl(38 92% 50%)` | Refunded status chip — amber, never renders as Completed even when `status: COMPLETED` |

**Accent reserved for — exact list, nothing else:**
1. Active sidebar nav state (History item, when selected)
2. Completed status: icon-tile background/ink (`chip-sage` family) — the ONE status this phase renders in sage
3. Summary strip icon tiles for the **Orders** and **Revenue** tiles only (`tint: sage`) — Avg tile uses neutral slate tint, Refunds tile uses terracotta tint (matches existing `screen-orders.jsx`/`screen-history.jsx` tile-tint convention)
4. Day-group header revenue figure text color
5. "All" status-filter pill background when selected (rendered dimmed/inert per D-14 — the token is still sage, just at reduced opacity)

Accent is NOT used for: row hover background (uses neutral warm tint `#faf7ef`), the "30 days" period-preset selected pill (uses `--sc-foreground` dark/near-black, matching the existing period-pill convention in the design source — distinct from status-pill selection which uses sage).

## Row & Table Layout Contract (D-06, D-05, D-02)

**Grid definition — 7 data columns + 1 chevron affordance track (8 tracks total), replacing the
design source's 9-track `HIST_GRID`:**

```
grid-template-columns: 150px minmax(200px, 1.8fr) 118px 78px 116px 132px 116px 34px;
/*                     order  customer            type   time  pay    status total chevron */
```

Rationale for the rebalance: the dropped items-count track (66px) and the dropped sub-line rows
(order-source label, customer-address line — both cut per REQUIREMENTS.md "Design Elements Cut")
are absorbed by widening the customer track's flex share (`1.6fr → 1.8fr`, min `150px → 200px`).
No blank cells — every remaining track carries a real column.

**Column contract, left to right:**

| # | Column | Content | Style |
|---|--------|---------|-------|
| 1 | Order | 30×30 status-tinted icon tile + `#dailyNumber` (D-05: fall back to short UUID slice when `dailyNumber` is null) — single line, no source sub-label | 14px / 900 / tracking -0.01em |
| 2 | Customer | `customerName` only — no address sub-line (no address field on `AdminOrder`) | 13.5px / 600, `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` |
| 3 | Type | `chip chip-slate` with `typeMeta()` icon + label (reuse `src/screen-orders.jsx` `typeMeta`, which already maps `local → Dine-in`). No table-number suffix — no table field on `AdminOrder` (cut, confirmed in REQUIREMENTS.md) | chip, 12–13px |
| 4 | Time | Local-day time `HH:mm` (D-04: local Romanian day boundaries, not UTC) | 13px / 600 / muted-foreground / tabular-nums |
| 5 | Payment | Icon + label. **Deliberate deviation from the design source for consistency with the rest of the app:** map `cash→'cash'`, `card→'card'`, `online→'wifi'` (matches `OrderCard`/`OrderDetailScreen`; the design source collapses online into the card icon — do not follow that) | 12.5px / 600 / muted-foreground |
| 6 | Status | Exactly one chip (D-02: refunded wins over completed) — `chip-sage` Completed / `chip-red` Canceled / `chip-amber` Refunded | chip |
| 7 | Total | Right-aligned. Canceled rows: strikethrough + `opacity: 0.6` (dim). Refunded rows render at full opacity (money was collected) | 14.5px / 900 / tabular-nums / tracking -0.01em |
| 8 | Chevron | Static `chevRight` icon, 16px, muted-foreground, centered — never rotates (no expand state) | icon-only |

**Row interaction:** `cursor: pointer`, hover background `#faf7ef` (120ms transition) — matches the
design source's existing hover treatment. Click navigates to the detail route (D-07/D-08); it does
NOT expand inline (the `HistoryReceiptRow` component in `screen-history.jsx` is dropped entirely —
do not port it).

**Row height:** consistent, unpadded by conditional sub-lines now that both row sub-labels are cut
— `13px vertical / 20px horizontal` padding, single-line content throughout. This equalizes all
row heights, which matters for the loading-skeleton contract below (skeleton rows must match this
exact height, no layout jump on data arrival).

**Table header row:** unchanged in style from the design source — `11px 20px` padding, `#faf6ec`
background, `10.5px / 700 / uppercase / 0.06em tracking` labels: `h_col_order`, `h_col_customer`,
`h_col_type`, `h_col_time`, `h_col_payment`, `h_col_status`, `h_col_total`, and an empty 8th cell
for the chevron track.

## Day-Group Header Contract (D-10, D-11, D-12)

Flex row, `justify-content: space-between`, padding `9px 20px`, background `#fcfaf4`, border-top +
border-bottom `1px solid hsl(120 10% 93%)`.

- **Left:** day label (`h_today`/`h_yesterday` + localized weekday/date, or plain localized date for
  older days) — 12.5px / 800 / tracking -0.01em.
- **Right:** `{count} {noun}` · `{revenue}` — e.g. "6 comenzi · 553,15 lei".
  - **Count** = every visible row in that day, **including** canceled and refunded (D-11).
  - **Revenue** = sum of **completed-only** rows' totals (D-10) — canceled and refunded contribute
    nothing; render in `var(--sc-primary)` / weight 800.
  - Sort newest-first within the day (D-12) and days newest-first overall.
  - Plural handling: `h_orders_count_one` ("comandă"/"order") vs `h_orders_count_other`
    ("comenzi"/"orders") — a 1-order day must read "1 comandă", not "1 comenzi".

## Summary Strip Contract (D-15 — client-computed, no `getAdminDashboard`)

4-tile grid, `repeat(4, 1fr)`, gap 12px, each tile a `.card` with a 44×44 icon tile + label/value/sub
stack — identical visual shape to the design source's summary strip, but **all values derived from
the same fetched-and-filtered order list that backs the day-grouped rows** (D-15). One data source,
one loading state, no independent failure mode for the strip.

| Tile | Label | Value (computed) | Sub | Icon tint |
|------|-------|-------------------|-----|-----------|
| Orders | `h_orders` | count of all visible (finished) orders | `h_period_30` | sage (accent) |
| Revenue | `h_revenue` | sum of completed-only totals | `h_period_30` | sage (accent) |
| Avg | `h_avg` | revenue ÷ completed-order count (— if zero completed orders) | `h_avg_sub` | slate (neutral) |
| Refunds | `h_refunds` | **count only** — no amount (D-15/D-10: no `refundAmount` field exists) | `{cancelCount} {h_canceled_suffix}` | terracotta |

Zero-state (list loaded successfully but is empty): tiles show computed zeros (`0`, `0,00 lei`,
`—` for avg, `0`) — NOT dashes. Dashes are reserved for the error state only (below), to keep
"no data yet" visually distinct from "failed to load."

## Filter Bar Contract — Inert (D-14)

The full filter bar (period presets, status/type filter pills, search input, Export button) renders
at its final visual position and size — **visible, dimmed, not clickable** — so later phases can
wire it up without any layout shift.

- Container: `opacity: 0.5` on the whole bar, **except** the "30 zile" / "30 days" period pill,
  which renders at full opacity/selected styling (dark `--sc-foreground` background, white text) —
  it reflects real current state, per D-14.
- All buttons/inputs: `disabled` (or `pointer-events: none` + `cursor: not-allowed`), no `onClick`
  handlers wired.
- Status filter pills show their real live counts is **out of scope** this phase — render static
  placeholder pills (`h_status_completed`/`h_status_canceled`/`h_status_refunded` + `all`) with no
  counts, or counts omitted entirely until Phase 10 (Filters + Search) wires them.
- Search input: placeholder text `h_search` visible, input disabled.
- Export button: visible with `download` icon + `h_export` label, disabled.

## Loading / Error State Contract (D-16)

**No layout jump** between loading → error/content — the inert filter bar already reserves the
page's shape; only the summary strip and table body swap content.

**Loading:**
- Summary strip: 4 tiles render in place, icon tile replaced by a neutral grey pulsing block,
  value/label/sub replaced by grey rounded bars (shimmer animation) at the same widths as real
  content.
- Table: header row renders normally (static labels, no loading state needed). 6–8 skeleton rows
  render at the **exact same row height** as real rows (13px/20px padding, single line) with grey
  shimmering block placeholders per column (30px circle for the icon tile, bar shapes for text/chip
  columns). No day-group header renders during loading (skeleton rows are ungrouped).

**Error:**
- Summary strip: all 4 tiles show `—` (em-dash) in place of the value; icon tiles render in neutral
  grey (not their normal tint) to signal "no confirmed data," not the empty-state's colored zeros.
- Table: the entire table body area (header row still renders) is replaced by a centered message —
  `h_error_title` + reused `check_connection` body copy + a `h_retry` button (`btn-secondary` style,
  `refresh` icon) that re-triggers the query.

## Detail Route Contract — Phase 7 Partial Scope (D-07, D-08, D-09)

Rows navigate to a detail route instead of expanding inline. **Phase 7 ships the route and a
minimal read-only view using ONLY the `AdminOrder` fields already fetched by the list call** —
`customerName`, `customerPhone`, `orderType`, `total`, `paymentType`, `createdAt`, derived status.
The full itemized receipt (`items[]`, address, handled-by, prep time) requires `getOrder(id)` and
belongs to the next phase (roadmap_impact "NEW" phase) — **do not attempt to render an items list
this phase; there is no item data to show.**

Because the data shape here has no `items[]`, the existing `OrderDetailScreen` (`screen-detail.jsx`)
two-column itemized/thermal-ticket layout cannot be reused as-is (it assumes `order.items` exists
and iterates it). For Phase 7, build a **minimal single-column read-only summary** reusing the
existing card/chip visual language (not the full component):

- Back button: `btn-ghost`, `arrowLeft` icon, new key `h_back_to_history` (ro: `Înapoi la istoric` ·
  en: `Back to history`) — returns to the History screen (not `orders`).
- Header block: order number (32px/900, same treatment as `OrderDetailScreen`'s header) + status
  chip + type chip + payment chip + formatted local time.
- Customer card: name + phone (if present) — no address (not available this phase).
- Total card: total only, no line-item subtotal/tax/delivery breakdown (not available this phase).
- No thermal ticket preview, no advance/cancel/print buttons — this view is read-only by
  construction (nothing to mutate, nothing to print yet).
- Long customer names wrap (do not truncate) — more horizontal space is available in the detail
  view than in the table row.
