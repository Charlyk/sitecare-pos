## Spacing Scale

Declared values (must be multiples of 4). Source: `styles.css` established pattern, confirmed across Phases 1–4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip dot padding, tight inline separators |
| sm | 8px | Button gap (icon + label), field stack gap, toggle-label gap |
| md | 16px | Card internal padding unit, grid column gap, section stack gap |

Exceptions:
- Printer Setup form fields: vertical gap between each field row is 16px (multiples-of-4 standard; replaces the prior 14px prototype value).

- Printer icon tile inside port dropdown items: 40×40px, `border-radius: 8px` — matches established `nav-item .icon` pattern; 10px border-radius replaced with nearest multiple-of-4 value.
- Receipt preview panel: `padding: 16px` — replaces prior 18px value.

## Typography

Source: `src/colors_and_type.css` — do not introduce any sizes or weights outside this scale.

**Outfit type scale (2 weights):** 600 (all functional text — labels, body, UI strings) and 900 (all headings). No other Outfit weights are permitted in Phase 5 components.

| Role | Size | Weight | Line Height | CSS Token / Class |
|------|------|--------|-------------|-------------------|
| Screen heading | 24px | 900 | 1.2 | inline style: `fontSize: 24, fontWeight: 900, letterSpacing: '-0.02em'` |
| Section heading (card title) | 16px | 900 | 1.2 | inline style: `fontSize: 16, fontWeight: 900, letterSpacing: '-0.02em'` |
| Body / label | 13px | 600 | 1.5 | inline style: `fontSize: 13, fontWeight: 600` (matches nav-item, btn-primary, btn-secondary) |
| Meta / field label | 11px | 600 | 1.4 | inline style: `fontSize: 11, fontWeight: 600, color: var(--sc-muted-foreground)` |

**Note on size consolidation:**
- Subtitle text in the form card header uses **13px** (Body / label row above) — not 14px.
- Inline error text below the status chip uses **11px** (Meta / field label row above) — not 12px.
- All body-level strings (placeholder text, option labels, toggle labels) use 13px/600.

**Separate font families — not counted in the 2-weight Outfit scale:**
- Eyebrow accent: `font-family: Caveat, cursive; color: var(--sc-terracotta); font-weight: 700; font-size: 18px` — use `.eyebrow` class. In Phase 5, the eyebrow reads `"thermal printer"` (EN) / `"imprimantă termică"` (RO) above the screen heading. Caveat is a decorative display font and its weight is independent of the Outfit scale.

**Locked exceptions — ThermalTicket component only:**
- The `ThermalTicket` component (`src/screen-detail.jsx:253`) uses 15px/900 for its preview heading ("Bon de test" / "Test ticket") and 11px monospace for receipt body text. These values are frozen from Phase 1 and must NOT be changed by the planner or executor. They exist solely inside `ThermalTicket` and do not propagate to any other Phase 5 component. The 15px value is excluded from the 4-size maximum because it is an immutable inherited component, not a new design decision.

### Order Detail Screen — Print Buttons (no structural change)

Two buttons already exist in `screen-detail.jsx` (lines 208–212):

### Port Dropdown

Render a `<select>` element populated from the `list_serial_ports` Tauri command result. Each `<option>` shows the port name (e.g., "COM3", "/dev/tty.usbmodem1") with no additional suffix. If the enumeration returns an empty list, render a single disabled option: "No ports found" (EN) / "Niciun port găsit" (RO). The `<select>` uses the existing input border/radius/font pattern from `.search` input.

### Status Chip

Reuse existing `.chip` class with semantic modifier:
- Success: `class="chip chip-sage chip-dot"` — "Printer connected" (EN) / "Imprimantă conectată" (RO)

Chip appears in the form card below the Printer Name field. It replaces itself on each Save attempt (no accumulation).

### Toast Notifications

No new toast structure. Icons: `check` for success, `zap` for error (matches existing `app.jsx` line 181 pattern).

## Interaction States

### Save Button Flow

1. **Idle (no config saved):** Save enabled. Test Print disabled (opacity 0.45, pointer-events none). Status chip: not shown.
2. **Loading (save in progress):** Save button text changes to "Saving…" (EN) / "Se salvează…" (RO), button disabled. A `cursor: wait` on the button parent. Do not use a spinner — text change is sufficient and consistent with Phase 4 patterns.
3. **Save success:** Status chip appears — `chip-sage chip-dot` "Printer connected". Test Print button becomes enabled. Config is persisted to plugin-store.
4. **Save failure:** Status chip appears — `chip-red chip-dot` "Connection failed". Inline error text below chip. Config is NOT persisted. Save re-enables immediately (staff can retry with a different port).

### Test Print Flow

1. **Pre-condition:** Only enabled after a successful Save. If not yet saved, opacity 0.45, pointer-events none, no tooltip needed.
2. **Triggered:** Calls Tauri `test_print` command. Button text changes to "Printing…" (EN) / "Se printează…" (RO), disabled.
3. **Success:** Toast success — "Test print sent" / "Print de test trimis". Button returns to "Test Print".
4. **Failure:** Toast error — "Print failed — check printer connection" / "Printare eșuată — verificați conexiunea". Button returns to "Test Print". No retry.

### Order Print Flow (from Order Detail)

1. Staff clicks "Print kitchen" or "Print customer".
2. If printer not configured: toast error — "Printer not configured — go to Printer Setup" / "Imprimanta nu este configurată — mergeți la Imprimantă".
3. If configured: Tauri `print_receipt` command invoked with order data + print kind.
4. Success: toast success — "Receipt printed" / "Bon printat".
5. Failure: toast error — "Print failed — check printer connection" / "Printare eșuată — verificați conexiunea".

### Offline State

When `isOffline` is true:
- Save button: disabled with `.btn-disabled-offline` (opacity 0.45, pointer-events none)
- Test Print button: disabled with `.btn-disabled-offline`
- Print buttons in Order Detail: disabled with `.btn-disabled-offline`
- No additional visual indicator needed beyond this — the global offline banner already communicates the connectivity state.

## Receipt Content Contract

The `ThermalTicket` JSX component defines the visual preview. The ESC/POS byte output from the Rust command must mirror the same content structure:

**Header block:**
- Restaurant name (UPPERCASE, centered, bold) — from `restaurantSettings.restaurant_name`
- Address (centered, small) — from `restaurantSettings.branch_address` (omit if null)
- Phone (centered, small) — from `restaurantSettings.branch_phone` (omit if null)
- Dashed separator: `"--------------------------------"` (32 chars)

**Identifier block:**
- `"Comanda #<dailyOrderNumber>    <time>"` — left + right aligned
- `"<orderType>    <source>"` — left + right aligned
- Customer name if present: `"Client: <name>"`
- Delivery address line if delivery order (omit for dine-in/pickup)

**Kitchen ticket only — banner line:**
- Inverted (black bg, white text): `"*** BON BUCĂTĂRIE ***"` (RO) / `"*** KITCHEN TICKET ***"` (EN)

**Items block:**
- Each item: `"<qty>x <NAME>"` left-aligned, price right-aligned (customer ticket only)
- Modifiers as sub-line: `"  -> <mod1>, <mod2>"` indented 2 spaces

**Notes block (if order has notes):**
- Dashed separator
- `"NOTE:"` bold
- Note text, small

**Totals block (customer ticket only):**
- Dashed separator
- `"Subtotal          XX.XX"`
- `"TVA 19%           XX.XX"` — use order.tax field; if null/0, omit line
- `"Livrare           XX.XX"` — only if `order.deliveryFee > 0`
- `"Discount         -XX.XX"` — only if `order.discount > 0`
- `"TOTAL RON         XX.XX"` (bold, 13px in preview = ESC/POS double-height)
- `"Plată             CASH"` (or card — from `order.payment`)

**Footer:**
- Dashed separator
- `"Mulțumim! / Thank you!"` centered (bilingual per D-10, always both languages)
- `"sitecare.ro"` centered
- Auto-cut command (always on — per D-12, no toggle UI in v1)
