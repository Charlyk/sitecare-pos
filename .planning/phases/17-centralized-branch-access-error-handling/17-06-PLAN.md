<objective>
Extend the existing window-focus listener so the app revalidates the server's selected branch on
every focus (not only when currentBranch is null), catching a branch change or access revocation
made on another device and routing it through the same recovery paths (BERR-04, D-06/D-07).

A benign remote change to a different valid branch is silently adopted with a neutral info toast;
a revocation/zero-branch state trips the NO_BRANCH_ACCESS block; the same branch is a no-op. A
reentrancy guard prevents rapid-alt-tab races on POS terminals.

Purpose: closes the "another device changed my branch and I never find out" gap (Pitfall 8), and
provides the D-02 auto-clear-on-focus trigger for the NO_BRANCH_ACCESS block.
Output: a generalized, race-guarded focus revalidation wired to the central recovery flow.
</objective>

| Boundary | Description |
|----------|-------------|
| window focus -> getMe() round-trip | client event triggers a server truth fetch; server is the sole authority on the selected branch |
| adopted server branch -> caches/SSE | setCurrentBranch re-scopes Phase 14 caches + Phase 15 SSE; must preserve branch isolation |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-17-05 | Information Disclosure | silent branch adoption on focus | low | mitigate | Adoption always fires the neutral "Now showing <branch>" toast so the board never silently swaps under staff (prevents a wrong-branch action); adoption uses server-confirmed selectedBranch only, never a client guess |
| T-17-02 | Input Validation | getMe() focus response | medium | mitigate | selectedBranch === null and a 403-status getMe error both fail safe to the NO_BRANCH_ACCESS block; id comparison is type-normalized so a malformed id can't force a spurious adopt; reentrancy guard prevents a stale response winning |
| T-17-03 | Information Disclosure | focus info toast copy | low | mitigate | Localized branch_focus_update_* copy; no raw SDK strings rendered |
</threat_model>
