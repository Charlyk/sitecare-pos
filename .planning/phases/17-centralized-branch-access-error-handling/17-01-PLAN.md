<objective>
Establish the ONE central branch-access-403 recovery path end-to-end for a single recoverable
code (BRANCH_ACCESS_REVOKED), proving the architectural spine before any expansion.

Wire TanStack Query's global QueryCache/MutationCache `onError` in `main.jsx` to a new
`handleBranchError(err, queryClient)` in `use-branches.js`, and wire the reopen consumer in
`shell.jsx` so the recovery is observable end-to-end (toast + switcher reopen + `['branches']`
refetch). This is the tracer: it touches every layer the phase modifies (config wiring →
data-layer dispatch → store flag → i18n copy → presentation consumer) for one path only.

Purpose: catch any architectural dead-end (does MutationCache.onError really subsume the switch
call? does the reopen seam fire?) on the first commit rather than after ten layers land.
Output: a runnable central path for BRANCH_ACCESS_REVOKED, verified against a synthetic 403.
</objective>
