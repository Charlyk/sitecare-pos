<objective>
Ship the end-to-end branch-switch happy path as a production-quality tracer: a multi-branch selector in the sidebar footer whose selection fires a non-optimistic `useBranchSwitch()` mutation, sets `currentBranch` only on success, and bridges the resulting SSE reconnect behind a global blocking overlay that releases into a success toast. This is the trigger slice for the whole v1.2 milestone — Phases 13/14/15 built `currentBranch`, branch-keyed caches, and branch-aware SSE; this plan wires the one action that actually sets `currentBranch`.

Purpose: prove the whole vertical (selector → switch → non-optimistic set → caches + SSE re-scope automatically → overlay bridge → toast) works on one path before Plans 02/03 expand it. Also relocates LANG-01 by deleting the RO/EN pill (frees the exact slot the selector occupies, D-02).

Output: `useBranchSwitch()`, `branchSwitcherForceOpen` store field, the full copywriting-contract i18n key set, a minimal multi-branch selector in `shell.jsx`, the switch orchestration + `SwitchingOverlay` in `app.jsx`, and end-to-end + unit tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (switch call) | `branchId` crosses to the server, which re-validates access server-side and returns the new session branch or a 4xx |
| app state → UI | `currentBranch` in Zustand drives every branch-scoped cache key and the SSE connection; a wrong value here mis-scopes everything downstream |
| pending window → order mutations | during a switch, an order mutation must not reach the server until the branch is confirmed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Tampering (of app state) | `useBranchSwitch` onSuccess / `currentBranch` | high | mitigate | D-05: `setCurrentBranch` runs ONLY in the mutation's `onSuccess`, never optimistically — `currentBranch` always reflects the last server-confirmed branch. Proven by Task 2 unit test. |
| T-16-02 | Elevation of Privilege (of timing) | pending-switch window / order mutations | high | mitigate | D-07: the global overlay (sibling of Shell, zIndex ≥ 200) covers all of Shell's children for the full pending+bridging window (SCOPE-04), so no Ring Up / Accept / Advance / Cancel / Reprint can land against the old-or-new branch mid-switch. |
| T-16-03 | Tampering (stale replay) | `currentBranch` / `branchSwitcherForceOpen` persistence | medium | mitigate | Both fields are session-only and excluded from `partialize`; a stale branch can never be replayed from disk on relaunch. |
| T-16-SC | Tampering (supply chain) | package installs | low | accept | Zero new packages this phase (RESEARCH: no install step) — no supply-chain surface introduced. |
</threat_model>
