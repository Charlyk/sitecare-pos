<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cart state → orders.create API | Cart items (productId, quantity) and order metadata flow from client state to API body |
| Discount calculation → API body | discountAmount is client-computed; no server validation — applied client-side to display total only |
| User input (customer fields, note) → API body | Text fields for customer name, phone, address, notes are sent to API as-is |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Tampering | orderType mapping | mitigate | orderTypeMap defined as module-level const — no user input; SDK validates enum server-side |
| T-04-06-02 | Tampering | discountAmount calculation | accept | Discount is staff-facing only; no security boundary; server computes authoritative total |
| T-04-06-03 | Information Disclosure | customer fields in order body | accept | Customer data is entered by staff for their own orders; no cross-customer leakage |
| T-04-06-04 | Denial of Service | rapid Ring Up clicks | mitigate | `createOrder.isPending` disables Ring Up while mutation is in flight; prevents double-submit |
| T-04-06-05 | Spoofing | productId from static vs live data | mitigate | Static MENU_ITEMS removed; productId now comes from SDK — server validates product existence |
</threat_model>
