## Spacing Scale

All spacing values are multiples of 4. Values extracted from `src/styles.css` inline usage and confirmed against the existing screens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap (`gap: 4`), chip padding tweaks |
| sm | 8px | Inline element gaps, chip padding (`gap: 8`), filter-bar gaps |
| md | 16px | Card inner padding (`padding: 16`), filter bar margin-bottom, stat strip gap |
| lg | 24px | `.content-pad` (`padding: 24`), modal horizontal padding, section gap |
| xl | 32px | Order detail header margin (32px font implies 32 context) |
| 2xl | 48px | Empty state padding (`padding: 48`) |
| 3xl | 64px | Topbar height (64px); use as minimum touch region for full-height rows |

Exceptions:
- **Topbar**: 64px height (not a spacing token — fixed layout dimension)
- **Sidebar**: 240px width (fixed layout dimension)
- **POS cart panel**: 380px width (fixed layout dimension)
- **AcceptDialog**: 460px width (fixed modal width)
- **Icon touch targets** (icon-btn): 38×38px — rounds to nearest 4px grid (accept 38px; do not change to 40px without prototype verification)
- **KDS advance button**: 40px height (not 38px) — intentional to be taller than header icon-btns

- Never use a font size below 10px in any element
- Eyebrow text (Caveat) is decorative only — one occurrence per section max
- Monospace font (`"SF Mono", "Menlo", "Courier New", monospace`) is reserved for thermal ticket preview only

**Terracotta reserved for:**
- `.btn-terracotta` (OrderDetail advance CTA)

## Interaction Contracts

### AcceptDialog (ACT-01)
- Opens when `state === 'new'` order is advanced (OrderCard or KDS).
- Preset times: delivery [20, 30, 45, 60, 75], pickup [10, 15, 20, 30, 45], dinein [10, 15, 20, 25, 30].
- Custom input: number, min 1, max 240.
- Confirm button disabled when `prep <= 0`.
- On confirm: call `updateStatus.mutate({ id, currentStatus: 'NEW', toStatus: 'ACCEPTED', estimatedMinutes: prep })`.
- On success: close dialog, push success toast. On error: push error toast, keep dialog open.
- Overlay: `rgba(18, 24, 18, 0.45)` + `backdropFilter: blur(4px)`.
- Animation: `fadeIn 180ms ease-out`.

### Cancel Order Dialog (ACT-03)
- Appears as a centered modal overlay (same overlay style as AcceptDialog).
- Width: 420px. Rounded corners: 20px (matches AcceptDialog).
- Contains: order number + customer name summary row, reason dropdown (5 presets), optional textarea for "Other" (visible only when "Altul / Other" selected, max 200 chars).
- Confirm button: disabled (`opacity: 0.45, pointer-events: none`) until a reason is selected.
- Call: `updateStatus.mutate({ id, currentStatus: order.state.toUpperCase(), toStatus: 'CANCELLED', reason: selectedReason })`.
- On success: close dialog, navigate back to orders screen, push success toast.
- On error: push error toast, keep dialog open.
- Cancel button ("Renunță") dismisses without API call.

### KDS Sound Alert (KDS-04)
- Audio file: `public/sounds/new-order.mp3` (committed to repo — short chime ~0.5s).
- Trigger: live SSE `order_new` events only, after snapshot flag is set.
- Snapshot detection: `useSSE` sets `snapshotReceived = true` after a 100ms timeout post-connect; events before that flag are snapshot events and silent.
- Mute toggle: `soundMuted` boolean in Zustand store (session-only, NOT in partialize).
- Mute button placement: KDS topbar header, right of topbar controls. Use `Icon name="bell"` (unmuted) / bell with slash (muted — add `bell-off` icon or apply cross overlay; use `x` icon overlay if `bell-off` not in registry).
- When muted: `new Audio(...).play()` is NOT called; all visual UX unaffected.
- When unmuted and live event fires: `new Audio('/sounds/new-order.mp3').play().catch(() => {})`.

### KDS Timer Interval (KDS-02)
- Current interval: `setInterval(30000)` — rerender every 30s.
- Requirement KDS-02 says "updated every minute".
- Contract: change to `setInterval(60000)` — 60 second rerender is sufficient to display minute-resolution elapsed time.

### POS Discount Field (POS-03)
- Placement: in the totals area between delivery fee row and total row.
- Layout: single row with label "Reducere / Discount" on left, toggle `%` | `RON` buttons in center, numeric input on right.
- Toggle: small segmented control, 2 options, default `%`.
- Input: number, min 0. For `%` mode: max 100. For `RON` mode: max subtotal.
- Discount line is hidden when input is empty or 0.
- When discount > 0: show "Reducere aplicată" line in totals with negative formatted amount (e.g., `-12,50 RON`).
- `discountAmount` in RON: calculate before submission. If `%` mode: `discountAmount = (subtotal * discountValue / 100)`. Pass to `orders.create` body; if API rejects field, apply client-side and omit from body.

### POS Menu (POS-01, POS-02)
- Replace static `MENU_CATEGORIES`/`MENU_ITEMS` imports with `useMenu()` hook output.
- Map SDK shape: `{ categories: [...], globalProducts: [...] }` → category tabs + item grid.
- Item card: 3-column grid, 72px icon area (gradient placeholder), item name (700 weight, 14px), description (11px muted), price (900 weight, 15px, `--sc-primary`).
- In-cart badge: absolute top-right, 22×22px, `--sc-primary` bg, white 900-weight quantity number.
- Out-of-stock items from API: render at `opacity: 0.45`, no click handler, show "Epuizat" chip overlay.

### Menu Availability Toggle (MENU-01, MENU-02)
- Replace `localStorage` state with `useMenu()` live data.
- `AvailSwitch` UI component is already correct — keep pixel-perfect as-is.
- On toggle: call `useMutation` → `client.kitchen.products.updateStock(...)` → `onSuccess: invalidateQueries(['menu'])`.
- While mutation is pending: apply `opacity: 0.6` to the row; switch toggle track changes color optimistically (can revert on error).
- On error: revert toggle state + push error toast.

### Settings Display Tab (SET-01, SET-02, SET-03)
- New tab added to existing tab bar: "Afișaj / Display", position last (after Integrations).
- Tab icon: use `Icon name="sliders"` — if not in icons.jsx, add path; fallback: use `settings` icon.
- Controls inside the tab: three sections separated by 16px vertical gap.
  - Language: `tw-seg`-style toggle (RO | EN). `setLang` from `useAppStore`.
  - Density: `tw-seg`-style toggle (Balanced | Dense). `setDensity`.
  - Accent: 4-color swatch picker — 4 buttons in a row. Each button is 40×40px rounded-full. Color: filled circle with matching accent color. Selected: white ring + scale(1.1). `setAccent`.
- On change: Zustand writes immediately, `@tauri-apps/plugin-store` persists automatically (via `partialize`).
- Show success toast "Preferințele au fost salvate / Preferences saved" 500ms after last change (debounced).

### Orders Search (ORD-03)
- Search input: placed in the filter bar, right of the type-filter pill, left of the Refresh/More buttons.
- Input style: matches existing `.search` class from styles.css (white bg, 1px border `--sc-border`, 10px radius, 8px+12px padding, 13px font, 280px width).
- Use `Icon name="search"` prefix inside input.
- Filter: client-side `orders.filter(o => o.dailyOrderNumber.toString().includes(q) || (customerName).toLowerCase().includes(q.toLowerCase()))`.
- When search is active and returns 0 results: show empty state with "Niciun rezultat" / "Search no results" copy (not the generic empty orders copy).
- Clear button (×): appears inside input right side when query length > 0.

### Offline Disabled State
- Already implemented in Phase 3 via `.btn-disabled-offline` class + `disabled` attribute.
- Phase 4 extends this to new buttons: AcceptDialog confirm button, Cancel dialog confirm button, POS "Ring Up" button.
- Offline state is `isOffline` prop passed from `app.jsx` → Shell → screen.
