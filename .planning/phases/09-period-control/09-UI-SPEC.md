# Phase 9 — UI Design Contract

> Visual and interaction contract for Period Control. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. This phase inherits the already-shipped design system
> (`src/colors_and_type.css` + `src/styles.css`) and the already-shipped inert filter bar
> (`src/screen-history.jsx:294-345`, `P7 D-14`) — this contract does **not** invent a new visual
> language. It (1) activates period pills that already exist in final visual position, (2)
> specs the ONE genuinely net-new surface — the custom-range popover, which the design handoff
> (`sitecare-orders/project/src/screen-history.jsx:159`) does not draw at all — and (3) specs the
> period-switch loading/error/copy behaviors decided in `09-CONTEXT.md` (D-01…D-14).

**Scope note:** Status/type filter pills, search input, and Export button stay inert this phase
(Phase 10/11) — untouched by this contract. The day-grouped list, the summary-strip render shape,
the empty-state component, and the detail route all ship from Phase 7 and are reused verbatim;
this contract only covers what retargeting the period touches.

## Visual Hierarchy

**Unchanged from `07-UI-SPEC.md` — this phase does not shift the screen's focal point.** The
primary focal point remains the summary strip's Revenue tile value (20px/900, the single largest
text on the screen), followed by the day-group revenue figures directly below it. This phase's
only net-new element competing for attention is the popover's Apply button (`.btn-primary`, sage) —
it is deliberately scoped to read as a **secondary, transient** focal point: it exists only while
the popover is open (a small, self-contained modal-like surface), never renders simultaneously with
the Revenue tile in the user's direct line of sight in a way that competes for it, and disappears
the instant a range is applied. The period pills themselves (selected state: dark `--sc-foreground`,
not accent-colored) are deliberately recessive by design, matching Phase 7's established
low-emphasis treatment of the filter bar relative to the data below it.

## Custom Range Popover Contract (D-01, D-02, D-03, D-04, D-09, D-10, D-11)

**The one genuinely net-new visual surface this phase adds.** No design mock exists for it
(`09-CONTEXT.md` flags this explicitly) — the layout below is this contract's own invention,
built entirely from already-shipped primitives (popover chrome from `shell.jsx`, buttons from
`styles.css`, field-label typography from the table header role).

**Trigger:** the Custom pill (4th in the period segmented control). Clicking it toggles the
popover open/closed regardless of whether a range is currently applied.

**Anchor & chrome** (copied verbatim from `shell.jsx:148-150`, the only popover precedent in this
codebase):
- Wrapping container: `position: relative` around the Custom pill button only (not the whole
  segmented-control group)
- Popover panel: `position: absolute`, `top: calc(100% + 6px)` (opens **downward** — this bar sits
  near the top of the screen, unlike the sidebar user-menu which opens upward), `left: 0`
- Panel chrome: `background: #fff`, `border: 1px solid hsl(120 10% 88%)`, `border-radius: 10px`,
  `box-shadow: 0 4px 16px rgba(0,0,0,0.12)`, `z-index: 50`
- Panel width: `280px`, `padding: 16px`
- Dismissal: outside-click (via `document` `mousedown` listener + `ref`, same mechanism as
  `shell.jsx:20-28`) **and** `Escape` key — both are the contract default (Claude's Discretion in
  `09-CONTEXT.md` left this open; this is the resolution, chosen for the low-risk standard popover
  convention). No dedicated close button — keeps the net-new footprint minimal, matching D-01's
  reasoning for rejecting a hand-built calendar

**Panel layout:**

```
┌────────────────────────────────────┐
│  DE LA              PÂNĂ LA        │  ← 10.5px/700/uppercase, 0.06em tracking
│ [__________]      [__________]     │  ← native <input type="date">, 8px gap between
│                                     │
│  ⚠ Intervalul maxim este de        │  ← 11px/600, var(--sc-destructive)
│     366 de zile.                   │     (only rendered when the typed/picked range
│                                     │      exceeds the cap or is otherwise invalid)
│                                     │
│         [ Aplică intervalul ]      │  ← .btn-primary, right-aligned, marginTop 16px
└────────────────────────────────────┘
```

- **D-02 (explicit Apply):** local popover state holds both dates; nothing is fetched until Apply
  Range is clicked. The button is `disabled` (visual: opacity `0.45`, `cursor: not-allowed` — matching the
  established `.btn-disabled-offline` dimming value at `src/styles.css:186`, not a new number)
  whenever: either field is empty, the range is invalid, or the range exceeds 366 days (D-09/D-10).
- **D-11 (guardrails at the input):** the End field's `max` = today; the Start field's `max` = the
  chosen End date (or today if End is empty); the Start field's `min` = End-minus-366-days once End
  is chosen. Both recompute as the other field changes. An Apply-time check still runs (native
  inputs accept typed values that bypass `min`/`max`) — this is where the cap message renders.
- **D-03 (pill shows the applied range):** once Apply succeeds, the Custom pill's label switches
  from `h_period_custom` ("Interval"/"Custom") to the formatted range (D-14, e.g. `3 mar. – 17 mar.`
  / `3 Mar – 17 Mar`), and the pill adopts the same **selected** styling as any other active preset
  (`var(--sc-foreground)` background, white text) — the `chevDown` icon stays visible next to it,
  signaling the popover reopens on click. The pill widens to fit its content (accepted cost, per
  D-03) — the segmented-control container is not fixed-width.
- **D-04 (switching to a preset clears custom):** clicking Today/7/30 while a custom range is
  applied reverts the Custom pill to its default "Interval"/"Custom" label and unselected styling,
  and the popover (if reopened later) starts empty — no remembered range.

## Period Switch — Loading Contract (D-05, D-06)

**Deliberately distinguishable from the greyed-out/inert convention** (`P7 D-14`'s 0.5-opacity +
`not-allowed` cursor) — D-05 requires the dimming to read as *loading*, not *disabled*, and both
conventions render on this screen at once (inert status/type/search/Export controls vs. a
mid-switch period list).

- **Rows & day-group headers:** stay visible at `opacity: 0.6` (a value distinct from the inert
  bar's `0.5`), no `pointer-events: none`, `cursor` stays at its normal `pointer` value — this is
  data settling in place, not a disabled feature.
- **Summary-strip tiles:** stay visible at the same `0.6` opacity treatment (not the shimmer
  skeleton — that's reserved for first-load per `07-UI-SPEC.md`; a period switch already has a
  previous value to dim, per `keepPreviousData`).
- **New loading affordance — a small spinning `refresh` icon (16px, `var(--sc-muted-foreground)`),
  positioned inline next to the selected pill** (or at the table card's header-row right edge —
  planner's placement call within this constraint). Uses one new CSS keyframe, `spin` (`800ms linear
  infinite` rotation) — the only new animation this phase adds; no existing spin keyframe exists in
  `src/styles.css` to reuse.
- **D-06 (label follows data, not the click):** the rendered tile sub-label and any "you are viewing
  X" text derives from **the range that produced the currently-displayed rows**, not from
  `selectedPeriod`. During the dimmed in-flight window, the sub-label still reads the PREVIOUS
  period's text (e.g. "30 zile") until the new data lands, at which point label and rows flip
  together. The selected pill (which DOES reflect the click immediately) is what communicates
  intent during the wait — the dimming visually ties pill-intent to tile-lag so the mismatch never
  reads as a bug.

## Period Switch — Error Contract (D-07, D-08)

**Reuses Phase 7's exact error visual, unmodified — this is a deliberate consistency choice, not an
oversight.** Per D-07: "exactly one error treatment exists on the screen, matching first-load
failure." This diverges from Phase 8's "keep what you already have" instinct (`P8 D-07`) —
deliberately, per the user's explicit choice recorded in `09-CONTEXT.md`.

- **Table body:** the entire body area (header row still renders) is replaced by
  `screen-history.jsx`'s existing `ErrorBlock` component — `h_error_title` + `check_connection` +
  `h_retry` button, `56px` centered padding — **unchanged from `07-UI-SPEC.md`**. The previously
  visible (dimmed) rows are discarded, not kept.
- **Summary strip:** reuses the existing `isError` branch already built in
  `screen-history.jsx`'s `SummaryStrip` (all 4 tiles show `—`, icon tiles render neutral grey) —
  **unchanged from Phase 7**. No new visual is introduced; the only change is that this branch must
  now also trigger on a period-switch failure, which falls out of the same `isError` flag TanStack
  Query already exposes regardless of which fetch failed.
- **D-08 (attempted range stays selected):** the pill the user clicked stays in its selected visual
  state through the error — Retry re-fetches THAT range, not the last-successful one. Clicking a
  different (previously-successful) pill restores its cached list instantly with no error flash, no
  refetch — a direct visual consequence of the per-range query-key cache already in place.
