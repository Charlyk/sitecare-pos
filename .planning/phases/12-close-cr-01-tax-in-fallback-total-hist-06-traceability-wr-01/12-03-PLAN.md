<assumption_delta_decision>
- **Noun:** History UI selection state (period / status / type / search).
- **Decision:** add-alongside — introduce a NEW session-only `historySelection` store slice that
  mirrors the established `selectedOrder`/`historyOrder` session-only template (set via an action,
  reset by `setScreen`, excluded from `partialize`) per CONTEXT D-01 and STATE.md's documented
  session-only pattern. This is NOT a promotion or generalization of an existing abstraction — it is
  idiomatic reuse of the shipped pattern.
- **Rationale:** the assumption-delta detector fired on the word "fallback" in the phase TITLE
  ("tax-in-fallback-total"), which refers to `normalizeOrder`'s fallback value path, not a
  singular→plural identity change — a false positive. The genuine new noun (`historySelection`) is
  an additive slice alongside two existing session-only slices, so add-alongside is correct and no
  promote/generalize is warranted. Advisory, non-blocking; recorded per planning instruction.
</assumption_delta_decision>

<objective>
The one substantive code change of Phase 12: lift History's period/status/type/search selection out
of `screen-history.jsx`'s four component-local `useState` calls into a session-only Zustand
`historySelection` slice (D-01), so the selection survives the History→history-detail→Back
round-trip (D-02) but still resets to defaults when leaving History for any other screen (D-03) —

mechanism. Make Phase 8 SC4's "period intact" literally true.

`setScreen`; `screen-history.jsx` rewired to read/write the store; both test files updated.

</objective>
