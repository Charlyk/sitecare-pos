# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase hydrates an already-shipped screen (`screen-detail.jsx`, `readOnly` mode
shipped in Phase 7) via `getOrder(id)`. It does not introduce a new screen or a new visual language.
The vast majority of the render surface — header, chips, customer card, items rows, thermal ticket —
already exists and already works off `normalizeOrder()`'s output; this contract governs only the
**net-new** surface: the duration row, the items-card loading skeleton, the items-card inline error,
and the one folded visibility fix (the ungated "Modify" button). Every token below is a value **already
present** in the codebase — nothing new is invented, per CLAUDE.md's design-fidelity rule.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled inline-style components + CSS custom properties (no shadcn/Tailwind in this project) |
| Preset | not applicable |
| Component library | none — React function components, inline `style={{}}` objects, shared utility classes (`card`, `chip-*`, `btn-*`) defined outside Tailwind |
| Icon library | custom SVG path set, `src/icons.jsx` (`<Icon name="..." size={n} />`) |
| Font | "Outfit" (sans, weights 300–900) for all UI text; "Caveat" (handwriting) reserved for marketing accents only, not used in this phase |

**Why no shadcn gate was run:** `components.json` is absent and this is a Vite/React project, which
would normally trigger the shadcn init question. It was skipped deliberately: CLAUDE.md's Design
Fidelity section requires the shipped hand-rolled system (`src/colors_and_type.css` + inline styles)
be matched pixel-for-pixel, and 7 phases (41 v1.0 requirements + Phase 7) have already shipped without
shadcn. Introducing a component library here would contradict the explicit, standing project
instruction rather than serve it. Registry safety gate: not applicable.

## Spacing Scale

This codebase does not enforce a strict 8-point scale — `screen-detail.jsx` and its siblings use the
exact pixel values below, and pixel-perfect fidelity means **reusing these values verbatim**, not
rounding them onto a fresh scale.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| Item row padding | `12px 18px` | Real item rows (existing) and skeleton item rows (new) — must match exactly so the skeleton→content swap causes no layout jump (D-06) |
| Row gap | `12px` | Icon-tile-to-text gap, reused unchanged in skeleton rows |
| Card section label margin | `8px` | Below uppercase section labels (`CUSTOMER`, etc.) — unchanged, no new usage |
| Error block padding | `56px` (screen-history.jsx `ErrorBlock`) → **use `32px 18px`** here instead | The items-card error replaces card *contents*, not a full screen area; screen-history's 56px is sized for a full-width empty page, not a card slot. 32px vertical / 18px horizontal keeps the error block visually inside the existing card's padding rhythm (18px is the card's own horizontal padding) |
| Retry button top margin | `16px` | Matches `screen-history.jsx` `ErrorBlock` exactly (D-07 "mirrors P7 D-16's retry-in-place pattern") |
| Header meta row top margin | `4px` | Unchanged — `marginTop: 4` on the existing `orderTimeLabel` / duration line |

Exceptions: none beyond the above — all values are lifted directly from existing code, not newly chosen.

## Duration Row — Placement & Format

Not covered by reused code; this is the one genuinely new rendering surface (D-10). Placement follows
the discretion note in `08-CONTEXT.md`: "follow the design's existing meta-row treatment."

- **Where:** inside the existing header meta line (`screen-detail.jsx` line ~47–49), which today reads
  `{orderTimeLabel(order.placedAt)} · {formatDuration(elapsed)} {t('elapsed').toLowerCase()}`. For
  `readOnly` orders, the trailing `formatDuration(elapsed) elapsed` segment (elapsed-since-now is
  meaningless for a finished archived order — it would show hours or days) is **replaced**, not
  appended, by the derived duration segment:
  - Completed: `{orderTimeLabel(order.placedAt)} · {t('h_prep_time')}: {formatDuration(prepMinutes)}`
  - Canceled: `{orderTimeLabel(order.placedAt)} · {t('h_canceled_after')}: {formatDuration(cancelMinutes)}`
  - Neither event exists (Claude's discretion, `08-CONTEXT.md`): drop the segment entirely — render
    only `{orderTimeLabel(order.placedAt)}`, no dangling separator
- **Format:** reuse the existing `formatDuration(minutes)` helper from `src/data.jsx` verbatim —
  `"25 min"` under 60 minutes, `"1h"` / `"1h 5m"` at and above 60. Do not write a new formatter.
- **Typography/color:** identical to the line it replaces — 12px, `var(--sc-muted-foreground)`, no icon
  (the existing line has none; do not add one).
- **Derivation:** `prepMinutes` = minutes between `order.placedAt` and the `COMPLETED` event's
  `createdAt`; `cancelMinutes` = minutes between `order.placedAt` and the `CANCELLED` event's
  `createdAt`. Both from `order.events[]` (D-10). Not `estimatedMinutes`.

## Items-Card Loading State (D-06)

Skeleton rows inside the *existing* items card shell — the card's header ("N items") is itself part of
what's loading, so the whole card content area is skeletal, not just the rows below a real header.

- **Row count:** 3 skeleton rows (Claude's discretion — "match the design's item-row height"; 3 is a
  representative default that fills the card without presupposing an unknown real count)
- **Row shape:** each skeleton row uses the **exact same** `padding: '12px 18px'`, `gap: 12`, and
  `borderBottom: '1px solid hsl(120 10% 94%)'` as a real item row (`screen-detail.jsx` line ~134), so
  swapping skeleton → real content causes zero layout jump (D-06's explicit requirement)
- **Skeleton bar shapes** (mirrors `screen-history.jsx`'s `SkeletonRow` fill treatment exactly —
  `hsl(210 15% 92%)`, `borderRadius: 4`):
  - Icon tile: 32×32px, `borderRadius: 8` (matches the real qty-tile's own radius)
  - Name bar: `60%` width, 14px height (matches item-name font size)
  - Price bar: 48px width, 13px height
  - Total bar: 56px width, 13px height, right-aligned (`justifySelf: 'end'` or `marginLeft: auto`)
- **Card header while loading:** skeletal too — a `100px`-wide, 15px-tall bar in place of "N items"
  text (card header font is 15px/900 per existing markup); the Modify button slot stays empty (it is
  gated by `readOnly` regardless of loading state, per the folded fix below)

## Items-Card Error State (D-07, D-08)

Replaces the entire items-card content (header + rows) with an inline message — the card shell (`card`
class, same outer dimensions) stays, so the layout doesn't reflow when the summary above it is already
on screen (D-07's "summary stays on screen" requirement is satisfied by this staying scoped to the
items card, never touching the header/customer/totals region above it).

```
┌─────────────────────────────────────────┐
│  [card, padding: 32px 18px, centered]    │
│                                           │
│         Nu am putut încărca bonul        │  ← 15px/600, var(--sc-foreground)
│    Verifică conexiunea și încearcă din   │  ← 13px/400, var(--sc-muted-foreground), marginTop 4
│                nou.                      │
│                                           │
│           [ ↻ Reîncearcă ]               │  ← btn-secondary, marginTop 16
│                                           │
└─────────────────────────────────────────┘
```

- Reuses `screen-history.jsx`'s `ErrorBlock` component pattern verbatim (icon: `refresh`, size 14,
  inside a `btn-secondary` button) — same visual language between the list's error state and the
  detail's error state
- One generic message regardless of 401 vs 404 vs network (D-08) — no conditional copy, no status
  branching
- Retry re-triggers the same `useOrderDetail(id)` query (TanStack Query v5 `refetch`) — no new fetch
  logic, just re-invoking what D-01 already returns

## Folded Fix — Ungated "Modify" Button

`screen-detail.jsx:131` currently renders `<button className="btn-ghost"><Icon name="edit" size={13}/>
{Modify label}</button>` unconditionally inside the items-card header. This is a **visibility** fix, not
a new visual element — no new token is needed:

- Gate: wrap in `{!readOnly && (...)}`, matching the existing gating pattern already used at lines 59,
  99, 106, 228, 240, 256
- Layout consequence: when hidden, the items-card header's `justify-content: space-between` naturally
  leaves the "N items" label as the sole child — no CSS change needed, the flex container already
  handles a single child correctly
- Per the planner's sweep instruction (`08-CONTEXT.md`): treat this as one finding, not the only one —
  re-check the whole file for any other interactive control not already covered by the six existing
  `readOnly` gates before considering SC3 satisfied
