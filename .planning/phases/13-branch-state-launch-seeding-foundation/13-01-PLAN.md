<objective>
Deliver the launch-seeding foundation for BSTATE-01: the app resolves and holds the current active branch (SelectedBranch or null) from server session state on BOTH entry paths — interactive sign-in and cold-start session restore — and never from local persistence. As a byproduct (D-05), this also closes the pre-existing gap where a remembered-session relaunch left authUser null and the sidebar fell back to a hardcoded name.

Purpose: Every later v1.2 phase (cache re-scoping, SSE reconnect, switcher UI, 403 recovery) depends on currentBranch being a reliably-seeded, session-only fact. This plan is that seam.

Output: A session-only currentBranch Zustand field, getMe() seeding at two auth seams plus a focus-retry backstop, and a corrected sidebar displayName.

## SDK Coverage Decision (ai-integration contribution)
Adopted this phase: `client.auth.getMe()` (returns CurrentUser directly or throws with .status — NOT the {data,error} fields style). Deferred: `client.me.branches.switch()` / `useBranchSwitch()` and `branchSwitcherForceOpen` → Phase 16 (no dead code shipped now, per D-08). This plan does not read or gate anything on currentBranch yet — no consumer exists until Phase 16.
