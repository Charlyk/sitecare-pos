<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App→Shell→Screens | isOffline boolean flows down the component tree; derived from SSE connection state |
| SSE event→orderCount | Order status strings from SSE events are used to filter the orders array for count |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-08 | Tampering | orderCount filter | accept | orderCount is derived from TanStack Query cache which was populated from authenticated API responses. Cache is in-memory only (no persistence). Worst-case: attacker can manipulate their own session's memory — no multi-user attack surface in a single-user desktop app. |
| T-3-09 | Denial of Service | isOffline=true blocks mutations | accept | Intended behavior: mutations blocked when SSE is down. The SSE reconnect backoff prevents hammer-reconnect. Server-side rate limiting is not a Phase 3 concern. |
| T-3-10 | Elevation of Privilege | btn-disabled-offline bypass | accept | pointer-events: none + disabled attribute prevent clicks. Keyboard bypass via Enter key is also blocked by the native disabled attribute. Server validates all mutation requests independently; client-side disabling is UX-only. |
</threat_model>
