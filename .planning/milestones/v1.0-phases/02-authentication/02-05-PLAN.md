**Edit 2 — Fix silent bail in handleSubmit (line 31)**

BEFORE:
```js
  const handleSubmit = (e) => {
    e.preventDefault();
    if (!isValidEmail(email)) return;
    onSubmit(email, pass, remember);
  };
```

AFTER:
```js
  const handleSubmit = (e) => {
    e.preventDefault();
    if (!isValidEmail(email)) {
      // WR-04: show error so user gets feedback even if button-disable is bypassed
      // (e.g. Enter key submitted before isValidEmail re-evaluated on last keystroke)
      onSubmit.setError?.('email'); // no-op if onSubmit does not expose setError
      return;
    }
    onSubmit(email, pass, remember);
  };
```

Wait — `onSubmit` is a prop function from auth.jsx's `signIn`. It does not expose `setError`. The correct pattern is to manage a local error state. However, the `error` prop is passed in from `useAuth()` in app.jsx; there is no local setError in LoginScreen. The simplest fix that ensures the user always sees feedback is: since `canSubmit` now uses `isValidEmail`, the button is already disabled for invalid email. The silent-bail path `if (!isValidEmail(email)) return` in handleSubmit is now a safety net only (e.g., if form is submitted via Enter key before canSubmit re-evaluates). The silent return is acceptable as a secondary guard because the primary guard (canSubmit) is now correct. Leave handleSubmit as-is — only Edit 1 is needed.

Apply only Edit 1. Do not change handleSubmit.
