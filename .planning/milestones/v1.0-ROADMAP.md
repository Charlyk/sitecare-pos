# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-22
**Phases:** 1–6
**Total Plans:** 35 plans + 4 quick tasks

## Overview

First production release of SiteCare POS — a Tauri v2 desktop app (macOS + Windows) that ports the Claude Design prototype pixel-perfectly and wires all 7 screens to the live SiteCare API. Restaurant staff can see, accept, and advance orders in real-time from a native desktop app. Includes real-time SSE kitchen display, secure authentication, thermal printer integration, and a full CI/CD release pipeline with macOS notarization and silent auto-updates.

## Milestone Summary

**Key Decisions:**

- `decorations: true` (native OS chrome) — avoids `@tauri-apps/plugin-window-state` bug #14822
- @microsoft/fetch-event-source for SSE (not native EventSource) — required to send Bearer auth headers
- Zustand owns UI state only; TanStack Query owns all server state — clean separation prevents cache conflicts
- `snapshotDone ref (100ms)` in useSSE — distinguishes initial SSE snapshot from live events; prevents sound burst on load
- `statusToSDK map` at module level — maps UI state names to SDK enum values with fallback `.toUpperCase()`
- `MIN_RETRY_MS = 30_000` floor on auth refresh — prevents tight async loops on already-expired tokens
- BILD-03 deferred: Windows unsigned MSI produced; Azure Trusted Signing is future path
- App icon generated from sitecare.svg with cream background

**Issues Resolved:**

- CR-01: scheduleRefresh tight-loop — fixed with 30s MIN_RETRY_MS floor
- WR-01: setScreen('login') invalid persist target — fixed to setScreen('orders')
- WR-02: stale error on login screen reappear — fixed with setError(null) in signOut/expireSession
- SSE-01: SSE disconnects on window background — fixed with `openWhenHidden: true`
- POS-05: toast showing `##123` double prefix — fixed to use `dailyOrderNumber` canonical field
- UI-DENSITY-01: density toggle not cascading — fixed CSS class-based density cascade

**Issues Deferred:**

- BILD-03: Windows code signing — unsigned MSI; Azure Trusted Signing documented for v1.1
- Tax calculation: server-authoritative total used; client-side Romanian VAT rates deferred
- Thermal printer hardware testing: approved-no-hardware pattern used; full hardware validation deferred

**Technical Debt Incurred:**

- Quick tasks (logout chip, hide settings tabs, product images, refresh button) executed post-phase outside the plan structure
- Traceability table in REQUIREMENTS.md not kept in sync after Phase 2 (checkboxes show 11/41 checked, all are complete)
