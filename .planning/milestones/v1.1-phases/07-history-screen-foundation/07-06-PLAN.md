    Add one `useEffect` to `src/app.jsx`, placed with the other effects and BEFORE the auth-guard
    early returns, mirroring the shipped role-gate effect at lines 182-184:

    when `screen === 'history-detail'` and `historyOrder` is falsy, call `setScreen('history')`.
    Dependencies: `[screen, historyOrder, setScreen]`.

    Why this exists (RESEARCH Pitfall 6 / UI-SPEC E7 backstop): `store.js`'s `partialize` persists
    `screen` but deliberately NOT `historyOrder` — order objects would go stale on disk. So quitting
    the app while viewing a history order detail rehydrates `screen: 'history-detail'` with
    `historyOrder: null`, and Task 1's router branch `&&`-short-circuits to nothing: a blank main
    content area inside a working shell. Not a crash, but not a screen either. The redirect sends the
    user to the list they came from.

    Do NOT extend this to `screen === 'detail'` / `selectedOrder`. That path has the same structural
    shape, but `selectedOrder` is a FETCHED value (`useOrderDetail(selectedOrderId)`, line 67) driven
    by the persisted `selectedOrderId`, so its rehydrate behavior differs and it is shipped v1.0 code
    outside this phase's scope. Changing it here would be an unscoped regression risk.
