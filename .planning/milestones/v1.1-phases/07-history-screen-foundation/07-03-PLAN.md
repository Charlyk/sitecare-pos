## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → SiteCare API (`GET /v1/admin/orders`) | The only network call this phase makes; carries the admin Bearer token |
| SiteCare API → client | `AdminOrder[]` (customer PII, financial totals) crosses into the app |
| SSE stream → TanStack Query cache | `use-sse.js` writes into `['orders']`; History reads a neighbouring cache root |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08 | Tampering | `['history-orders']` vs the SSE-owned `['orders']` cache root | high | mitigate | Distinct key root pinned by an acceptance criterion (`grep -c "\['orders'\]"` returns 0). A shared root would let `use-sse.js`'s `setQueryData` inject kitchen-shaped `Order` objects into History's `AdminOrder[]` cache — silently corrupting the day-grouped list and its revenue figures with no error surfaced. This is the phase's one high-severity threat and it is fully mitigated in-plan |
| T-07-09 | Elevation of Privilege | `/v1/admin/orders` scoping per restaurant / per role | medium | transfer | Server-side responsibility — the admin token's scope is enforced by the API, not the client. The client cannot mitigate it. If the token lacks access the SDK returns `result.error` (401/403), which this hook rethrows into the D-16 error state; no silent success path exists (ASVS V4) |
| T-07-10 | Information Disclosure | Raw SDK error text reaching the UI | medium | mitigate | The hook rethrows `result.error.error` as the Error message. Plan 04's error state renders the STATIC i18n `h_error_title` + `check_connection` copy and must NOT render `error.message` — so server-side detail never reaches the screen. Note the SDK type already documents that `paymentWarning` never contains raw Stripe error text |
| T-07-11 | Information Disclosure | Console/log leakage of PII from the queryFn | low | mitigate | The `queryFn` contains no `console.*` call; orders are returned, never logged |
| T-07-12 | Spoofing | CSP `connect-src` coverage for the new endpoint host | low | accept | No new host: `/v1/admin/orders` resolves to `https://api.restaurant.sitecare.ro`, already present in `src-tauri/tauri.conf.json` `connect-src`, and the `client.admin.*` namespace is already in production use (`use-stats.js`, `use-restaurant-settings.js`). No CSP change is required — verified, not assumed |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package install in this phase (RESEARCH.md "Package Legitimacy Audit": not applicable). No `[ASSUMED]`/`[SUS]` packages, so no legitimacy checkpoint is required |
