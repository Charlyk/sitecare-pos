# Requirements Archive: SiteCare POS Desktop App — v1.0 MVP

**Archived:** 2026-05-27
**Milestone:** v1.0 MVP (SHIPPED 2026-05-22)
**Original Defined:** 2026-04-22
**Core Value:** Restaurant staff can see, accept, and advance orders in real-time from a native desktop app that looks exactly like the design prototype.

---

## v1 Requirements — All Complete ✅

### Foundation

- [x] **FOUND-01**: Tauri v2 + React 18 + Vite 6 scaffold builds successfully on macOS and Windows
- [x] **FOUND-02**: @charlyk/admin-client installs from GitHub Package Registry in local dev and CI environments
- [x] **FOUND-03**: All 7 prototype screens converted from `window.*` globals to ES module imports/exports
- [x] **FOUND-04**: Zustand store manages UI state (screen, role, lang, accent, density, sidebar, toasts) with @tauri-apps/plugin-store persistence
- [x] **FOUND-05**: CSS design tokens from prototype (`colors_and_type.css`) imported and working in Vite without modification
- [x] **FOUND-06**: Tauri CSP configured to allow API domain in `connect-src` (blocks SSE and fetches if missing)

### Authentication

- [x] **AUTH-01**: User can log in with username + password via @charlyk/admin-client
- [x] **AUTH-02**: Auth token is persisted in OS secure storage (macOS Keychain / Windows Credential Manager), not localStorage
- [x] **AUTH-03**: App proactively refreshes auth token before expiry to cover full 8-hour shifts
- [x] **AUTH-04**: App auto-logs in on restart when a valid stored token exists (remember device)
- [x] **AUTH-05**: All screens are protected by an auth guard — unauthenticated users are redirected to login screen

### Orders

- [x] **ORD-01**: User can view a live list of orders with status filtering (new, accepted, preparing, ready, done)
- [x] **ORD-02**: User can switch between FOH (cashier) and BOH (kitchen) role views
- [x] **ORD-03**: User can search orders by order ID or customer name

### Order Actions

- [x] **ACT-01**: User can accept a new order and set prep time — triggers `new → accepted` transition with prep-time picker dialog
- [x] **ACT-02**: User can advance order status through the lifecycle: `preparing → ready → done` (and `ready → out → done` for delivery)
- [x] **ACT-03**: User can cancel an order from the Orders list or Order Detail screen
- [x] **ACT-04**: User can print a receipt for any order from the Order Detail screen

### Kitchen Display

- [x] **KDS-01**: Kitchen display shows live order queue updated in real-time via SSE (no polling)
- [x] **KDS-02**: Each ticket shows elapsed time since the order was placed, updated every minute
- [x] **KDS-03**: Tickets visually indicate urgency by age — green (fresh), yellow (waiting), red (overdue)
- [x] **KDS-04**: App plays a sound alert when a new order ticket arrives on the KDS
- [x] **KDS-05**: User can bump (mark done) a ticket directly from the KDS screen

### POS

- [x] **POS-01**: User can browse the live menu with categories and items fetched from the API
- [x] **POS-02**: User can add items to a cart and adjust quantities before checkout
- [x] **POS-03**: User can apply discounts (per-item or whole order) during checkout
- [x] **POS-04**: User can select order type (dine-in, pickup, delivery) before submitting
- [x] **POS-05**: User can submit a completed order to the kitchen via the API

### Menu Management

- [x] **MENU-01**: User can toggle item availability (in-stock / out-of-stock) from the Menu screen
- [x] **MENU-02**: Menu screen shows current availability state loaded from the live API

### Printer

- [x] **PRNT-01**: User can configure thermal printer connection (USB or TCP) in the Printer Setup screen
- [x] **PRNT-02**: User can send a test print from the Printer Setup screen
- [x] **PRNT-03**: App prints receipts via ESC/POS protocol using a Tauri native plugin (system print dialog is incompatible with thermal printers)

### Settings

- [x] **SET-01**: User can change app language (Romanian / English), persisted across app restarts
- [x] **SET-02**: User can change display density (balanced / dense), persisted across app restarts
- [x] **SET-03**: User can change accent theme color, persisted across app restarts

### Offline Resilience

- [x] **OFF-01**: App shows a visible "connection lost" banner when the API is unreachable
- [x] **OFF-02**: Existing data remains visible from TanStack Query cache while offline
- [x] **OFF-03**: Mutating actions (accept, advance, cancel, create order) are disabled while offline and re-enabled on reconnect

### Build Pipeline

- [x] **BILD-01**: GitHub Actions CI builds on every push and produces platform installers on release tags
- [x] **BILD-02**: macOS .dmg installer with Apple notarization (required for Gatekeeper on macOS 13+)
- [x] **BILD-03**: Windows .msi installer with code signing (avoids SmartScreen reputation warnings)
- [x] **BILD-04**: App checks for and installs updates automatically via Tauri updater
