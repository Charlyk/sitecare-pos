<objective>
Make the live SSE order stream (`src/use-sse.js`) branch-aware: reconnect scoped to the new branch as soon as `currentBranch?.id` changes, re-key every cache write to Phase 14's branch-scoped keys, preserve snapshot-silence across the reconnect, and add a non-behavioral 403 capture scaffold — all without a switcher UI (that is Phase 16).

Purpose: Close the last branch-awareness gap after Phase 14's fetch-hook re-scoping. Pre-Phase-15, the SSE stream keeps streaming the OLD branch's events after a switch and writes to orphaned unscoped keys no branch-scoped hook reads — the silent-stale-stream failure this phase exists to prevent (SCOPE-02).

Output: A rewired `src/use-sse.js` (one file) plus extended `src/__tests__/use-sse.test.js` covering the reconnect mechanism, scoped-key alignment, captured-not-live-read isolation, single-branch regression, snapshot silence, and the capture scaffold.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE server → client cache | Server-pushed `order_new`/`order_status_changed` events cross into the client-side TanStack Query cache via the SSE handlers (untrusted JSON, already `JSON.parse`-in-try/catch guarded). |
| Aborted old connection → new branch cache | An in-flight message from a just-aborted stale connection could, if branch is live-read, write into the NEW branch's cache (cross-branch bleed). |
| 403 response body → client log | A non-2xx onopen body (D-06 capture) may carry server-supplied fields into a client-side log. |
