<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| branch list → popover render | the server-scoped accessible-branch list (`useBranches()`) is the only source for which branches are offered; the popover never lists a branch the server did not return |
| app state → selector affordance | `branches.length` and `currentBranch?.id` from state decide read-only vs interactive and which row is checked |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-04 | Information Disclosure | popover branch list | low | accept | The popover lists only `client.me.branches.list()` results (server-computed accessible branches for this user, Phase 13) — no new listing surface; leaking "branches I could switch to" is not a new risk. |
| T-16-05 | Tampering (of app state) | selected-row checkmark / trigger label | medium | mitigate | Checkmark and trigger read `currentBranch` from the store, which only changes on server-confirmed switch (Plan 01 D-05) — a click never optimistically moves the checkmark (Pitfall 1). |
| T-16-06 | Spoofing (single-branch bypass) | `branches.length > 1` gate | low | mitigate | Read-only rendering is gated on `branches.length > 1`, never on `!!currentBranch`, so a single-branch tenant cannot be tricked into an interactive switch affordance (D-04). |
| T-16-SC | Tampering (supply chain) | package installs | low | accept | Zero new packages this phase. |
</threat_model>
