## Spacing Scale

This codebase's real convention is a **finer, non-strict-8pt scale** (verified against `shell.jsx`, `cancel-dialog.jsx`, `styles.css` — gaps of 4/6/8/10/12/14/16/18/20/24 all appear in already-shipped, human-verified UI). Declaring a purist 8pt-only scale would contradict 15 phases of shipped precedent and get flagged by the checker against the actual codebase. This phase follows the **real** convention:

| Token | Value | Usage this phase |
|-------|-------|-------------------|
| xs | 4px | icon-to-text gap inside the branch trigger pill |
| sm | 6px | popover offset from trigger (`bottom: calc(100% + 6px)`) — exact user-chip-menu precedent, reused verbatim |
| sm+ | 8px | popover internal item gap; footer button internal padding |
| md | 10–12px | popover row padding (`10px 12px`, matches `.user-chip` and the existing popover button in `shell.jsx:158`) |
| md+ | 14–16px | overlay message block padding; confirm-dialog body padding (matches `cancel-dialog.jsx` `16px 24px`) |
| lg | 24px | confirm-dialog header/footer padding (exact `cancel-dialog.jsx` precedent) |
| xl | 32px+ | overlay centered content max-width breathing room |

Exceptions: 6px, 10px, 12px, and 14px are retained (not rounded to the nearest 4px multiple) under the **LOCKED — Design-fidelity exception to the generic UI grid/weight rules** decision recorded in `PROJECT.md` Key Decisions (locked 2026-07-23). That decision formally waives the UI-SPEC checker's Dimension 5 (4px-multiple grid) project-wide for values matching the shipped design system (`colors_and_type.css` + `styles.css`, 15 phases live); this table's tokens are drawn verbatim from that shipped system (`shell.jsx`, `cancel-dialog.jsx`), so retaining them is compliant by the locked decision, not a violation of it.

## Typography

All sizes are on the existing `Outfit` scale already used across the sidebar/dialogs (no new font sizes invented for this phase beyond what's already load-bearing elsewhere).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 600 | 1.4 — branch name in the trigger pill and each popover row (exact match to `.user-chip` name: `fontSize:13, fontWeight:600`) |
| Label | 11px | 700, uppercase, `letter-spacing: 0.08em` | 1.3 — "default" badge text and any popover section label (exact match to `cancel-dialog.jsx`'s reason-picker label convention) |
| Heading | 20px | 800 | 1.25 — the overlay's "Switching to `<branch>`…" message (deliberately one step below `cancel-dialog.jsx`'s 22px/900 dialog title — this is a transient status line, not a decision-requiring dialog, so it reads slightly lighter) |
| Meta/sub | 12px | 500 | 1.4 — overlay secondary line (e.g. reconnecting status), toast detail text (matches existing `.toast` detail: `fontSize:13` — use 12–13px, never below) |

Weight budget for this phase: **600 (body/meta) + 700 (label) + 800 (heading)** — three weights, exceeding the UI-SPEC checker's generic 2-weight cap (Dimension 4). This is authorized, not a gap: the **LOCKED — Design-fidelity exception to the generic UI grid/weight rules** decision recorded in `PROJECT.md` Key Decisions (locked 2026-07-23) formally waives Dimension 4 project-wide for weights matching the shipped design system. All three weights (600/700/800) are already in active, human-verified shipped use across 15 completed phases (e.g. `.user-chip` name at 600, `cancel-dialog.jsx`'s reason-picker label at 700, dialog titles at 800/900) — this phase extends those exact tokens rather than introducing new ones.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | sidebar footer surface — `linear-gradient(180deg, #fbf6ea 0%, #f7f1e1 100%)` (existing `.sidebar`) | the switcher trigger and collapsed chip sit directly on this, unstyled background (no new box around the pill beyond what's specified below) |
| Secondary (30%) | `#ffffff` (`--sc-card`) with `1px solid var(--sc-border)` | popover surface, overlay message card, cart-discard confirm dialog — exact match to the existing user-chip-menu popover and `cancel-dialog.jsx` card treatment |
| Accent (10%) | `var(--sc-primary)` `hsl(120 14% 49%)` | reserved **only** for: (a) the checkmark on the currently-selected branch row in the popover, (b) the "default" badge's border/text when idle (mirrors `.chip-sage`), (c) the overlay's loading spinner (reuses the existing `.spin` keyframe), (d) the popover trigger's chevron-open state icon color |
| Destructive | `var(--sc-destructive)` `hsl(0 84.2% 60.2%)` | the "discard order" verb inside the cart-non-empty confirm dialog (D-13) — the confirm button only; **not** the generic failure toast (D-11 failure toast is neutral/error-toned like existing `kind: 'error'` toasts, not framed as destructive) |

Accent reserved for: selected-branch checkmark, "default" badge idle styling, overlay spinner, popover-open chevron color — nothing else in this phase's new UI uses `--sc-primary` as a fill (trigger pill background stays neutral/white-on-cream, matching the existing Collapse button's `background:#fff` convention, not a primary-tinted button).

**Primary visual focal point:** the current-branch name inside the sidebar-footer trigger pill is the element the eye lands on first — it sits at 13px/600 in the position of highest habitual attention in the existing footer stack (directly above the user chip, the sidebar's other identity element), so it must never be visually subordinated to the chevron, the "default" badge, or any icon in the same row.

## Copywriting Contract

Bilingual (`ro` canonical / `en` mirror) per `src/i18n.jsx` convention — every row below needs both locales added as new `I18N` keys.

| Element | Copy (ro) | Copy (en) |
|---------|-----------|-----------|

| Branch trigger (multi-branch) | `<branch name>` + chevron (down when closed, up when open — reuse `chevDown`/`chevUp` exactly as the user-chip menu does) | same |

| Popover section label (optional, only if >1 branch) | `Filiale disponibile` | `Available branches` |
| Overlay heading (in-flight) | `Se comută la <branch>…` | `Switching to <branch>…` |
| Overlay sub-line (while SSE still reconnecting after `switch()` resolved, before D-08 release) | `Se reconectează…` | `Reconnecting…` |
| Success toast title (SWCH-04, fires on overlay release — D-10) | `Filială schimbată` | `Branch switched` |
| Success toast detail | `Ești acum pe <branch>` | `You're now on <branch>` |
| Failure toast title (D-11, generic — no error-code branching) | `Nu s-a putut schimba filiala` | `Couldn't switch branch` |
| Failure toast detail | `Încearcă din nou` | `Try again` |
| Cart-discard confirm dialog title (D-13) | `Comanda curentă va fi anulată` | `Current order will be discarded` |
| Cart-discard confirm dialog body | `Schimbarea filialei șterge comanda POS în lucru. Continui?` | `Switching branches discards the in-progress POS order. Continue?` |

| Cart-discard confirm — secondary button | `Rămân aici` (mirrors `cancel-dialog.jsx`'s cancel-button convention of staying put) | `Stay here` |

Destructive actions in this phase: **one** — discarding an in-progress POS cart on branch switch (D-13). Confirmation approach: modal confirm dialog (styled per `cancel-dialog.jsx` precedent — header/body/footer card, destructive-colored primary action), gated only when `screen === 'pos'` AND the cart is non-empty; otherwise the switch proceeds immediately with no confirm step.
