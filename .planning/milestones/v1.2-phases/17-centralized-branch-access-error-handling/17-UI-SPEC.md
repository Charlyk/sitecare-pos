## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--sc-background` warm cream | the `NO_BRANCH_ACCESS` block's full-viewport background — it replaces Shell (sidebar hidden per D-01), so it owns the page surface directly; **not** a white card over a dark scrim like `CancelDialog`/`SwitchingOverlay` — this is a persistent full-page state, not a transient modal |
| Secondary (30%) | not used by the block (deliberately no card/box — see layout rationale below); `#ffffff` (`--sc-card`) continues to back the reopened branch popover (Phase 16 markup, unmodified) |
| Accent (10%) | `var(--sc-primary)` `hsl(120 14% 49%)` | reserved **only** for: (a) the block's Retry button fill (`.btn-primary`), (b) the Retry button's in-flight spinner color, (c) the existing `.toast-icon` tint (unchanged — all three new toasts reuse the current single tint, no per-code color variation) |
| Destructive | `var(--sc-destructive)` `hsl(0 84.2% 60.2%)` | **not used this phase** — none of the three `BRANCH_*` recovery paths are framed as destructive actions. The recoverable-code toasts render through the existing neutral `kind:'error'` toast styling (zap icon, sage-tinted icon tile, same as every other error toast in the app) — never red/alarm-colored, consistent with the project's carried-forward tone rule ("failure toast is neutral/error-toned, not framed as destructive") |

Accent reserved for: Retry button fill, Retry spinner color, existing `.toast-icon` tint — nothing else in this phase's new UI is primary-tinted. The block's own icon (`alert`, see below) is `--sc-muted-foreground`, deliberately **not** primary or destructive-colored, so the terminal blocking state doesn't read as either a call-to-action or an alarm.

**Primary visual focal point:** on the `NO_BRANCH_ACCESS` block, the eye must land on the headline first, then the Retry button — the block has exactly one interactive element, so there is no competition for attention. On the recoverable-code toast, the interpolated branch name inside the detail line is the piece of information staff must register before dismissing.

**Layout rationale (E1, not a taxonomy row but load-bearing):** the `NO_BRANCH_ACCESS` block is deliberately **not** styled as a floating white card over a dark scrim (unlike `CancelDialog`/`SwitchingOverlay`/`AcceptDialog`) — it is a **persistent full-page state**, not a transient modal, so it replaces `<Shell>` entirely (sidebar hidden, per D-01) and renders its centered text+button content directly on `--sc-background`. This mirrors `EmptyBlock`'s minimal, box-less, muted-foreground text convention (`screen-history.jsx:218-242`) rather than the heavier bordered-card dialog convention — chosen per D-01's explicit rejection of "a full branded/login-style gate screen."
