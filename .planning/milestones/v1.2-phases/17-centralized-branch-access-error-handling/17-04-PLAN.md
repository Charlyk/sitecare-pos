<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| noBranchAccess flag -> screen routing | the flag decides whether data screens render; must be a hard gate, not bypassable |
| Retry getMe() -> block clear | server truth (selectedBranch) is the only thing that may clear the block |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-01 | Tampering / Elevation of Privilege | NO_BRANCH_ACCESS top-level gate | medium | mitigate | The gate returns before <Shell>/the screen router renders, so a zero-access user cannot reach data screens via the UI; and even if the client flag were tampered, the server still re-validates selected_branch_id per request (the flag gates rendering only, never data access) |
| T-17-02 | Input Validation | Retry getMe() response | low | mitigate | Clear the block only on an explicit non-null selectedBranch; a malformed/empty response leaves the block up (fail-safe, no wrongful unblock) |
</threat_model>
